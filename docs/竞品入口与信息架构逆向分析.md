# 竞品入口与信息架构逆向分析

> 分析对象：**iLoveIMG**（`iloveimg.com/zh-cn`）、**Convertio**（`convertio.co/zh/`）、**CloudConvert**（`cloudconvert.com`）
> 抓取方式：REA `capture_browser_scenario`（Chromium 154 headless，viewport 1440×1200 / 1400，locale `zh-CN`，timezone `Asia/Shanghai`，`reduced_motion: reduce`，`service_workers: block`）
> 抓取产物：DOM 快照 + 可访问性树 + 截图 + URL/历史；本文结论全部来自 DOM 与截图，未依赖任何二手资料
> 分析动机：Pixora 上线格式转换能力后，用户反馈「**找不到入口**」——36 个转换页当时只在页面中段和页脚各有一个链接

---

## 1. 结论速览

三家竞品在「用户如何找到某个转换功能」这件事上分成两个流派，但**有一个共同点**：

| 竞品 | 首屏主体 | 格式发现路径 | 信息架构流派 |
|---|---|---|---|
| iLoveIMG | **13 张工具卡片网格** + 分类筛选条（全部/优化/创建/编辑/转换/安全） | 主导航直接列 6 个工具 + 「更多工具 ▾」按类别分组的面板 | **工具索引派** |
| Convertio | 单个转换器组件 + 「已转换 34.8 亿个文件」计数器 | 主导航「转换 ▾」下拉，按文件族分 8 个 hub 页 | 单组件派 |
| CloudConvert | 一个超大拖放区（h1 `Convert Any File`） | 极简导航（Pricing / Sign in / Sign up），格式在组件内选 | 单组件派 |

**共同点：格式矩阵始终距页面顶部只有一次交互。** iLoveIMG 用直接链接 + 分组面板，Convertio 用「转换 ▾」下拉。没有一家把长尾转换页藏到页脚。

**Pixora 原状（问题）**：导航 6 项全是锚点，没有任何一项指向 `convert/`；36 个转换页只能从页面中段（`#conversions` 的 6 张卡片）和页脚第 4 项进入。首屏完全看不到格式转换。

## 2. iLoveIMG —— 工具索引派

### 2.1 首页结构

DOM 标题层级极简，整页只有 2 个 `h2`：

```
h1  可批量编辑图片 的所有工具
h2  你的在线图片编辑器就在这里，而且永远免费！
h3  压缩图像文件 / 调整图像的大小 / 裁剪图片 / 转换至JPG文件 / JPG文件转换至
h3  照片编辑器 / 提升图片质量 / 去除背景 / 给图片加水印 / 搞笑创意图片生成器
h3  旋转一个图片 / HTML转图片 / 模糊面部
h2  通过高级版享受更多功能
```

**首页本身就是工具索引**，不是营销页：首屏 13 张工具卡，没有 hero 文案、没有工作流、没有 FAQ、没有对比表。

### 2.2 工具卡片标记

```html
<div class="tools__item" data-category="optimize">
  <div class="badge badge--new badge--soft">全新功能！</div>
  <a href="/zh-cn/upscale-image" title="提升图片质量">
    <div class="tools__item__icon"><svg width="100" height="100" …></svg></div>
    <h3>提升图片质量</h3>
    <div class="tools__item__content"><p>以高分辨率放大图像…</p></div>
  </a>
</div>
```

三个可复用的模式：
1. **`data-category` 驱动筛选** —— 分类条（优化/创建/编辑/转换/安全）不重排 DOM，只按属性过滤。
2. **每张卡片一个内联 SVG 图标**（100×100 视框，纯色填充），无图标字体、无额外请求。
3. **`badge--new` 标注新功能**，把新上线的能力推到视觉前排。

### 2.3 主导航

```
压缩图像文件 · 调整图像的大小 · 裁剪图片 · 转换至JPG文件 · 照片编辑器 · 更多工具 ▾
```

- 前 5 项是**具体工具**，不是分类。
- 第 6 项「更多工具」是**按类别分组的 mega-menu**，DOM 里的分组标题为 `优化` / `创建` / `转换` / `安全`（`<div class="nav__title">`）。
- 「**转换至JPG文件**」被提到一级导航——转换能力与编辑能力平权。

### 2.4 工具页（`/zh-cn/resize-image`）

```
h1  调整图像的大小
h2  你需要调整图片的大小吗? 使用我们的在线工具，可以按像素或百分比调整 JPG、PNG、SVG 和 GIF 图片的尺寸。
    ↑ 这句话里内嵌了 4 个子页链接：resize-jpg / resize-png / resize-svg / resize-gif
```

**工具页的副标题本身就是格式长尾的入口**——用户在看「怎么用」的时候顺手就能进到 `resize-jpg` 这类具体格式页。这是一个成本极低的内链位置。

工作区右侧是选项面板：
- **两个 Tab：按像素 / 按百分比**。百分比 Tab 提供 `缩小25% / 缩小50% / 缩小75%` 一键预设。
- 宽度 / 高度输入框，placeholder 为「自动」。
- 复选框：`保留长宽比`（默认勾选）、`如果像素较小则不放大`。
- 一个 `?` 帮助弹窗，解释宽高不一致时「按最大值处理」的语义。

免费额度写在拖放区下方：resizeimage 200MB / 30 个文件（未登录）、30（已登录）、120（高级版）。

**工具页没有 FAQ、没有营销区块**——工具就是全部内容，SEO 交给页脚和长尾子页。

## 3. Convertio —— 单组件派

### 3.1 首页结构

```
h1  文件转换器
h2  将您的文件转换成任意格式
h3  支持超过 300 种格式 / 快速简便 / 云端处理 / 自定义设置 / 安全保障 / 支持所有设备
h2  Conversion API
h4  整体转换质量评分
```

首屏是**一个转换器组件 + 一个实时计数器**：

```html
<div class="index-counter no-select">
  <div class="counter-box text-center">
    我们已转换 <b>3,485,715,861</b> 个文件，总大小为 <b>63,704</b> TB
  </div>
</div>
```

计数器是**信任信号**，用真实业务量替代形容词。Pixora 是端上工具、拿不到这个数字，但它有等价的诚实版本：本次会话实际处理了多少张、省了多少体积（已在 v1.2.0 实现）。

### 3.2 转换器组件

```html
<div class="converter-container">
  <div class="converter-wrapper tall">
    <div class="converter">
      <div class="file-source-button">
        <label for="pc-upload-add">选择文件</label>
        <div class="dropdown-menu file-source-nav">
          <input type="file" id="pc-upload-add" multiple>
          <label class="nav-item from-pc">从电脑</label>
          <span class="nav-item from-dropbox">从 Dropbox</span>
          <span class="nav-item from-drive">从 Google Drive</span>
        </div>
      </div>
      <div class="file-source-caption">
        <span>放置文件在这里. 1 GB 最大文件大小 或者 <a>注册</a></span>
      </div>
    </div>
  </div>
</div>
```

要点：
- 「选择文件」是一个**带下拉的按钮**，把三个来源（本机 / Dropbox / Drive）收进一个菜单，而不是并排三个按钮。
- 容量上限写在拖放区**正下方**，与拖放区形成一组。
- 组件高度用 `tall` 修饰类控制，说明他们按场景准备了多种组件高度。

### 3.3 主导航

```
Video Editor · Add Subtitles to Video · Compress Video · GIF Editor · Text to Speech · Video Translator · 更多
注册 · 登录 · 我的文件 0
转换 ▾ → 音频转换器 / 视频转换器 / 图像转换器 / 文档转换器 / 归档转换器 / 演示器 / 字体转换器 / 电子书转换器 / OCR
API · 定价 · Help
```

**「转换 ▾」下拉把 8 个格式族全部列出**，每个族是一个 hub 页（`/zh/image-converter/` 等）。这是 Pixora 导航下拉的直接参照物。

### 3.4 已知短板（前次分析结论）

仅部署 `Product` + `AggregateRating`，缺 `FAQPage` / `HowTo` / `SoftwareApplication`；10 个第三方脚本。Pixora 在这两点上是反超的。

## 4. CloudConvert —— 极致单组件

```
h1  Convert Any File
h2  Select your file to convert
h3  Company / Resources / Legal / Contact   ← 全部是页脚
导航：Pricing · Sign in · Sign up
```

整页首屏只有**一个超大拖放区**，所有信息架构压到页脚。这是「用户已经知道要来干什么」的极致假设，对新用户和 SEO 都不友好。Pixora 不采用这一路线。

## 5. 可落地结论与实施结果

### 5.1 结论对照表

| 竞品做法 | 出处 | Pixora 决策 | 落地位置 |
|---|---|---|---|
| 格式矩阵距顶部一次交互 | 三家共有 | **采纳** | 导航「格式转换 ▾」巨型菜单，5 列 × 7 链接 = 35 页 |
| 按目标/类别分组，而非平铺 | Convertio 8 族下拉；iLoveIMG 4 类面板 | **采纳** | 菜单与首页索引均按**输出格式**分组（转 PNG / JPG / WEBP / BMP / ICO） |
| 首页即工具索引 | iLoveIMG 13 卡网格 | **采纳（改造）** | `#conversions` 从 6 张手写卡片改为**全部 35 条链接的分组索引** |
| 工具页副标题内嵌格式子页链接 | iLoveIMG `resize-image` h2 | **采纳** | 工具区上方「直接按格式转换」快捷行 + `#formats` 区头部链接 |
| 百分比缩放 + 一键预设 | iLoveIMG 按百分比 Tab | **采纳** | 工具新增「按原图比例」`25% / 50% / 75% / 100%` |
| 「如果像素较小则不放大」 | iLoveIMG resize 工具 | **采纳** | 工具新增「不放大」开关（按轴钳制，缩小时不受影响） |
| 实时计数器做信任信号 | Convertio 34.8 亿文件 | **改造后采纳** | 端上工具无法诚实声称全局计数 → 改为**本次会话统计**（张数 / 原始体积 → 输出体积 / 减少百分比） |
| 容量上限写在拖放区下方 | Convertio | 参考 | Pixora 无容量上限（本地处理），改为在拖放区写明支持格式与批量 |
| `data-category` 筛选、`badge--new` | iLoveIMG | 不采纳 | 35 个页面只有一种类别（格式转换），加筛选条是伪需求；`badge--new` 同理 |
| 把信息架构全压到页脚 | CloudConvert | 不采纳 | 对新用户与爬虫都不友好 |
| 多来源（Drive / Dropbox）上传菜单 | Convertio | 不采纳 | Pixora 明确不上传，收录云盘来源与「零上传」定位自相矛盾 |

### 5.2 实施清单（v1.2.0）

**入口（直接回应用户反馈）**

1. 主导航新增「格式转换 ▾」`<details>` 巨型菜单 —— 5 列 × 7 链接，共 35 个转换页 + 1 个总览入口，**全站 37 个页面统一**。当前页在菜单内以 `aria-current="page"` 高亮。
2. 首页 `#conversions` 由 6 张卡片升级为 **35 条链接的分组索引**，标题改为「全部 35 种转换组合」。
3. Hero 次要 CTA 由「查看源码」改为「按格式转换」。
4. 工具区上方保留「直接按格式转换」快捷行（6 个热门 + 全部 35 种）。
5. `#formats` 区头部加入总览页链接。

**工具能力**

6. 「按原图比例」缩放：`25% / 50% / 75% / 100%` 四个 chip。批量场景下**按每张图自身像素**换算，因此不同尺寸的图片可以一起处理；激活时宽度输入框禁用并显示 placeholder「按原图」。再次点击同一比例、或点击任一常用宽度 chip、或手动输入宽度，都会退出比例模式。
7. 「不放大」开关：目标尺寸超过原图时按轴钳制回原尺寸。缩小方向不受影响。
8. 本次会话统计：`本次已处理 N 张 · 原始 X → 输出 Y · 减少 Z%`。
9. 新增 `?scale=` 深链参数（如 `?scale=50`），与既有 `?to=` / `?w=` / `?mode=` / `?q=` 一致。

**工程**

10. `tools/gen-convert-pages.mjs` 新增 `nav()` 与 `formatIndex()`，成为导航与首页格式索引的**唯一来源**，通过 `<!-- NAV:START/END -->`、`<!-- FMTINDEX:START/END -->` 标记自动同步 `index.html`。避免了两份拷贝各自漂移——而漂移正是当初入口丢失的根因。
11. **修复总览页死链**（由内链审计发现）：总览页位于 `/convert/`，却按「首页深度」生成导航，输出了 `convert/png-to-jpg/` 这类相对路径，实际解析为 `/convert/convert/png-to-jpg/`，35 条全部指向不存在的地址。根因是把「距站点根的距离」和「距 `/convert/ 的距离」压缩成了一个 `depth` 数字。改为显式的三态位置表：

    ```js
    const LOC = {
      root: { up: "",        conv: "convert/" },              // /index.html
      hub:  { up: "../",     conv: "./" },                    // /convert/index.html
      slug: { up: "../../",  conv: "../../convert/" },        // /convert/<slug>/index.html
    };
    ```

    这个 bug 在只看「链接是否存在」的检查下完全不可见，必须校验**链接解析后的目标是否真实存在**才会暴露。
